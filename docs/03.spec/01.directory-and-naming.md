# 01. ディレクトリ構成と命名規則

## 概要

AIcoのファイル構成を定める。  
本章では以下を定める。

* ディレクトリ構成
* ファイル命名規則
* プロジェクト資産との棲み分け
* マニフェスト仕様

## 1. ディレクトリ構成

AIco導入先のリポジトリでは、ソースコードやシステム設計書の既存配置を変更せず、以下のAIco関連ファイルを追加する。

```text
<project-root>/
├── AGENTS.md                        # 共通規約マスター（AIcoマーカー内＋プロジェクト固有領域）
├── CLAUDE.md                        # Claude Code用入口（@AGENTS.md のみ記載）
├── .agents/
│   ├── skills/                      # 共通スキルの原本（aico-*＋導入先固有スキル）
│   └── agents/                      # Antigravity用ワーカー定義（詳細：05章）
├── .claude/
│   ├── skills/                      # .agents/skills/ からの同期先
│   └── agents/                      # Claude Code用ワーカー定義
├── .codex/
│   └── agents/                      # Codex用ワーカー定義
├── .github/
│   ├── skills/                      # .agents/skills/ からの同期先
│   └── agents/                      # GitHub Copilot用ワーカー定義
├── tools/
│   ├── aico.sh                      # Linux用 人向けランチャー入口
│   └── aico.bat                     # Windows用 人向けランチャー入口
└── management/                      # 既定の管理ルート（変更可能）
    ├── index.md                     # 管理ルート入口＋ダッシュボード（区分サマリ・進行中チケット）
    ├── aico-manifest.json           # 導入済みAIcoの版・設定情報（ワーカーモデルSSOT含む）
    ├── 01.manual/                   # AIco由来：Getting Started・AGENTS.md参照用の詳細規約
    ├── 02.discussions/              # 議事録（直下に index.md、必要時 archived/）
    ├── 03.adr/                      # ADR（直下に index.md、必要時 archived/）
    ├── 04.tickets/                  # チケット（直下に index.md、必要時 archived/）
    ├── 05.runbooks/                 # Runbook（直下に index.md、必要時 archived/）
    ├── templates/                   # AIco由来テンプレート一式
    └── scripts/                     # AIco由来Pythonスクリプト＋_lib/
```

`AGENTS.md` は、AIcoと導入先プロジェクトの双方が更新するファイルである。  
AIcoが更新する範囲はマーカーで区切り（詳細は第3節）、導入先プロジェクト固有の規約はマーカー外へ記載すること。  
導入先プロジェクト固有の規約を別ファイルへ切り出して参照させる場合は、管理ルート（`management/`）の外で管理する。

以下の各区分フォルダ配下には必要に応じて `archived/` フォルダを配置する。  
管理ルート直下に全区分をまとめた `archived/` は設けないこと。

* `02.discussions/`
* `03.adr/`
* `04.tickets/`
* `05.runbooks/`（手順書単位のアーカイブは `05.runbooks/archived/<runbook>/`、個別の実施記録アーカイブは `05.runbooks/<runbook>/records/archived/<YYYYMMDD-HHMMSS>-<slug>/` へ分離配置する）

## 2. ファイル命名規則

### 2.1. 基本要素の書式

記録の識別子（ID）およびファイル名・フォルダ名は、以下の規則に従って構成する。

| 要素 | 書式 | 制約・補足 |
| :--- | :--- | :--- |
| **日時** | `YYYYMMDD-HHMMSS` | 15文字、ローカル時刻の秒まで付与し作成順と辞書順を一致させる |
| **種類** | `discussion` / `adr` / `ticket` | 省略形を使わずフルスペルで記述する |
| **`slug`** | `^[a-z0-9]+(?:-[a-z0-9]+)*$` | 英小文字・数字・単一ハイフンのみ。先頭・末尾・連続ハイフン不可。40文字以内を推奨する |
| **フェーズ（`phase`）** | `drafting` / `planning` / `design` / `implementation` / `closing` | チケット工程の識別子（詳細：`03`章）。レビュー指摘のファイル名に使用する |
| **ラウンド（`round<N>`）** | `round1`, `round2`, ... | レビュー実施回次（1始まりの整数）。省略せず `round` をフルスペルで記述する |
| **連番（`NNN`）** | `001`〜`999` | チケット内の補足ノートやレビュー指摘（ラウンドごと）に用いる3桁0埋め連番 |

### 2.2. 記録種別ごとのパスと識別子

| 対象 | パス形式 | 識別子（ID） |
| :--- | :--- | :--- |
| **議事録** | `management/02.discussions/<YYYYMMDD-HHMMSS>-discussion-<slug>.md` | `<YYYYMMDD-HHMMSS>-discussion-<slug>` |
| **ADR** | `management/03.adr/<YYYYMMDD-HHMMSS>-adr-<slug>.md` | `<YYYYMMDD-HHMMSS>-adr-<slug>` |
| **チケット** | `management/04.tickets/<YYYYMMDD-HHMMSS>-ticket-<slug>/index.md` | `<YYYYMMDD-HHMMSS>-ticket-<slug>` |
| **チケット内ノート** | `<チケットフォルダ>/notes/<NNN>-<slug>.md` | `<NNN>-<slug>` |
| **レビュー指摘（チケット）** | `<チケットフォルダ>/review/findings/<phase>-round<N>-<NNN>-<slug>.md` | `<phase>-round<N>-<NNN>-<slug>` |
| **レビュー指摘（Runbook実施記録）** | `<Runbook実施記録フォルダ>/review/findings/round<N>-<NNN>-<slug>.md` | `round<N>-<NNN>-<slug>` |
| **Runbook手順書** | `management/05.runbooks/<runbook>/runbook.md` | `<runbook>` |
| **Runbook実施記録** | `management/05.runbooks/<runbook>/records/<YYYYMMDD-HHMMSS>-<slug>/index.md` | `<YYYYMMDD-HHMMSS>-<slug>` |

固定名ファイル（`index.md`、`plan.md`、`runbook.md`、`README.md`、`AGENTS.md`、`CLAUDE.md`、`aico-manifest.json`）には日時を付与しない。  
Runbookの実施記録はサブフォルダと `index.md` で構成し、ログやスクリーンショットなどの添付ファイルを同一フォルダ内へ格納可能とする。必要に応じてレビュー記録（`review/`）も配下へ配置できる。

### 2.3. 重複・衝突時の扱い

作成時の自動連番付与（`-2` 等）は行わないこと。  
生成予定のファイルパスまたはフォルダパスが既存パスと完全に一致した場合は、上書きせずエラー（終了コード `1`）で停止し、別時刻または別 `slug` で再実行する。

## 3. プロジェクト資産との棲み分け

AIco関連ファイルと導入先プロジェクトの既存資産・固有設定が混在しないよう、所有領域とファイル内の更新境界（マーカー）を定める。

### 3.1. 所有領域の分類

アップデート時の誤上書きを防ぐため、リポジトリ内の全ファイルの所有者を以下の3区分で定義する。

| 領域 | 所有者 | 該当パス | 更新時の扱い |
| :--- | :--- | :--- | :--- |
| **AIco由来領域** | AIco | ・`AGENTS.md`（マーカー内）<br>・`CLAUDE.md`<br>・`.agents/skills/aico-*`<br>・`.agents/skills/` からの同期先スキル<br>・各ツール `agents/` 配下の AIco ワーカー定義（`worker-{high,middle,low}.*`、`management/templates/workers/` と `aico-manifest.json` から生成）<br>・`tools/aico.*`<br>・`management/01.manual/`<br>・`management/templates/`<br>・`management/scripts/` | アップデート手順・マイグレーション・同期スクリプトで差し替える<br>導入先で直接改造しないこと |
| **プロジェクト固有領域** | 導入先 | ・ソースコード・システム設計書などのプロジェクト資産<br>・`AGENTS.md`（マーカー外）<br>・`management/aico-manifest.json`<br>・導入先固有スキル（`.agents/skills/` 配下）・導入先固有エージェント定義（各ツール `agents/` 配下の `worker-{high,middle,low}.*` 以外）・固有ツール | AIcoの更新で上書きしてはならない<br>ただし `aico-manifest.json` の版更新や形式変更はマイグレーションスクリプトで行う |
| **作業記録領域** | 導入先 | ・`management/02.discussions/`〜`05.runbooks/` の各記録<br>・各 `index.md` の生成済み一覧 | 配布物の雛形で上書きしてはならない<br>形式変更はマイグレーションスクリプトで行う |

### 3.2. マーカー規約

1つのファイル内でAIco由来または自動生成の範囲と手書き範囲が共存する場合は、以下のHTMLコメントマーカーで境界を明示すること。

| マーカー種別 | 開始・終了行 | 用途 |
| :--- | :--- | :--- |
| **AIco管理ブロック** | `<!-- AICO:BEGIN -->` 〜 `<!-- AICO:END -->` | `AGENTS.md` など、AIcoアップデート時に差し替える固定規約範囲 |
| **自動生成ブロック** | `<!-- AICO:AUTO:BEGIN:<id> -->` 〜 `<!-- AICO:AUTO:END:<id> -->` | 各 `index.md` など、スクリプトが元記録またはGit差分から再生成する一覧範囲（`<id>` は `^[a-z0-9]+(?:-[a-z0-9]+)*$` の一意ラベル。例：`summary`, `active-tickets`, `list`, `changed-files`, `findings`） |

マーカーを書き換えるスクリプトは、以下の制約を守ること。

* **整合検査**：開始・終了マーカーの欠落、順序逆転、入れ子、`<id>` 不一致、または同一ファイル内での `AICO:BEGIN` 重複・同一 `<id>` の `AICO:AUTO` 重複を検出した場合は、ファイルを変更せず終了コード `1` で停止する。異なる `<id>` の `AICO:AUTO` ブロックは同一ファイル内に複数配置できる。
* **範囲外の保全**：マーカー外の文章・属性・改行コードは一切変更してはならない。

## 4. マニフェスト仕様

導入済みAIcoの版・環境設定・ツール別ワーカーモデル設定を一元管理（SSOT）するため、管理ルート直下に `aico-manifest.json` を配置する。  
スクリプト・`doctor`・同期処理・マイグレーションは本ファイルを基準に動作すること。

```json
{
  "schema_version": 1,
  "aico_version": "0.1.0",
  "source_repository": "https://github.com/sasaki819/AIco.git",
  "management_root": "management",
  "integration_branch": "develop",
  "tools": ["claude", "codex", "antigravity", "copilot"],
  "worker_models": {
    "claude": {
      "high": { "model": "", "effort": "" },
      "middle": { "model": "", "effort": "" },
      "low": { "model": "", "effort": "" }
    },
    "codex": {
      "high": { "model": "", "effort": "" },
      "middle": { "model": "", "effort": "" },
      "low": { "model": "", "effort": "" }
    },
    "antigravity": {
      "high": { "model": "", "effort": "" },
      "middle": { "model": "", "effort": "" },
      "low": { "model": "", "effort": "" }
    },
    "copilot": {
      "high": { "model": "", "effort": "" },
      "middle": { "model": "", "effort": "" },
      "low": { "model": "", "effort": "" }
    }
  }
}
```

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `schema_version` | integer | 必須 | マニフェスト自体のスキーマ版（初期値 `1`） |
| `aico_version` | string | 必須 | 導入済みAIcoのSemVer表記（例：`0.1.0`） |
| `source_repository` | string | 必須 | 配布元・アップデート参照先の Git リポジトリ URL（既定：`https://github.com/sasaki819/AIco.git`、完全オフライン専用運用は `""`）（詳細：`08`章） |
| `management_root` | string | 必須 | リポジトリルートからの管理ルート相対パス（既定：`management`） |
| `integration_branch` | string | 必須 | 統合ブランチ名（既定：`develop`、GitHub Flow導入先では `main` 等） |
| `tools` | string[] | 必須 | 導入先で使用する対象ツール一覧（`claude` / `codex` / `antigravity` / `copilot`） |
| `worker_models` | object | 必須 | ツール×ワーカー段階（`high` / `middle` / `low`）ごとの `{ "model": string, "effort": string }` 設定（詳細：`05`章） |
