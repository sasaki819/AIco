# 02. 記録構造・テンプレート・一覧仕様

## 概要

AIcoで管理する記録の書式とテンプレート・一覧の仕様を定める。
本章では以下を定める。

* 統一ステータス仕様
* YAML frontmatter 共通規約
* 記録別の構成とテンプレート仕様
* 一覧生成仕様

## 1. 統一ステータス仕様

記録種別をまたいで状態の意味を直感的に揃えるため、`open` / `in-progress` / `done` / `cancelled` の4値を共通語彙とする。
決定の有効状態を扱うADRのみ、採用・廃止を表す `accepted`・`deprecated` を併用する。
チケットにおける工程（フェーズ）とレビュー等のフェーズ内状態は、frontmatter の `phase` および `phase_status` で独立して管理する（詳細：`03`章）。

| 記録の種類 | 許容する `status` 値と意味 |
| :--- | :--- |
| **チケット** | ・`open`：起票・DoR確認中<br>・`in-progress`：進行中（調査・設計・実装・レビュー等を含む）<br>・`done`：完了<br>・`cancelled`：中止 |
| **レビュー指摘** | ・`open`：未選別<br>・`in-progress`：人間採用・対応中（修正〜独立再確認完了まで）<br>・`done`：独立再確認完了<br>・`cancelled`：見送り |
| **議事録** | ・`open`：未開始<br>・`in-progress`：議論中・保留<br>・`done`：結論・チケット化済み<br>・`cancelled`：見送り |
| **Runbook実施記録** | ・`in-progress`：実施中・中断中<br>・`done`：完了<br>・`cancelled`：中止 |
| **ADR** | ・`open`：提案・検討中<br>・`accepted`：採用中<br>・`deprecated`：廃止・置換済み<br>・`cancelled`：不採用・取り下げ |

一覧・ダッシュボードにおける `active` / `closed` の大区分は、`status` から機械的に以下の2値へ集約する（チケットおよび議事録で共通）。

* **`active`**：`open`、`in-progress`
* **`closed`**：`done`、`cancelled`

## 2. YAML frontmatter 共通規約

すべての管理ファイルは UTF-8（BOMなし）・LF改行とする。
YAML frontmatter の要否および `status` キーの要否は、**①独立した管理単位として一覧化・ID識別されるか**・**②記録自体がライフサイクル状態遷移を持つか** の2軸で以下のとおり定める。

| 対象ファイル | frontmatter | 共通必須キー |
| :--- | :--- | :--- |
| **状態遷移を持つ独立記録**（議事録・ADR・チケット `index.md`・レビュー指摘・Runbook実施記録） | 必須 | `id`, `title`, `status`, `created`, `updated`（＋2.2節の追加キー） |
| **状態遷移を持たない独立記録**（Runbook手順書 `runbook.md`・チケット内ノート `notes/<NNN>-<slug>.md`） | 必須 | `id`, `title`, `created`, `updated`（`status` は設けない） |
| **従属・集計ファイル**（チケット `plan.md`・各一覧 `index.md`・`review/index.md`） | なし | — |

### 2.1. 共通必須キーの仕様

| キー | 型 | 書式・説明 |
| :--- | :--- | :--- |
| `id` | string | 記録の一意識別子（`01`章の命名規則によるID） |
| `title` | string | 一覧に表示する短い件名（改行・タブ・先頭 `#` は不可） |
| `status` | string | 第1節で定めた許容値のいずれか（状態遷移を持つ独立記録のみ必須） |
| `created` | string | 作成日時（`YYYY-MM-DD HH:MM:SS`、ローカル時刻） |
| `updated` | string | 最終更新日時（`YYYY-MM-DD HH:MM:SS`、ローカル時刻） |

### 2.2. 種別ごとの追加キー

相互参照の属性値には、移動に強い不変のIDを記載する。
本文中で他記録へ遷移する場合は標準Markdownの相対リンクを用い、アーカイブ移動時はスクリプトでリンクを追従させること。

#### チケット（`index.md`）

| 追加キー | 型 | 必須／任意 | 説明 |
| :--- | :--- | :--- | :--- |
| `phase` | string | 必須 | 現在のフェーズ（`drafting` / `planning` / `design` / `implementation` / `closing`） |
| `phase_status` | string | 必須 | フェーズ内の状態（`working` / `reviewing` / `triaging` / `fixing` / `re-reviewing` / `done`） |
| `branch` | string | 必須 | 作業ブランチ名（導入先規約に従う。例：`feature/<チケットID>`） |
| `parent` | string \| null | 任意 | 親チケットID（単独チケット時は `null`） |
| `children` | string[] | 任意 | 子チケットID一覧（なければ `[]`） |
| `discussions` | string[] | 任意 | 関連する議事録ID一覧 |
| `adrs` | string[] | 任意 | 関連するADRのID一覧 |

#### レビュー指摘

レビュー対象のフェーズ（チケット時）とラウンドはファイル名および `id`（チケット時：`<phase>-round<N>-<NNN>-<slug>`、Runbook実施記録時：`round<N>-<NNN>-<slug>`）に含めるため、frontmatter へ重複定義しないこと。

| 追加キー | 型 | 必須／任意 | 説明 |
| :--- | :--- | :--- | :--- |
| `severity` | string | 必須 | `critical` / `major` / `minor` の3段階 |
| `reviewer` | string | 必須 | レビュー実施者（役割名・ツール名・モデル名、または `human` 等。例：`worker-middle (claude)`） |

#### 議事録

| 追加キー | 型 | 必須／任意 | 説明 |
| :--- | :--- | :--- | :--- |
| `tickets` | string[] | 任意 | 議論から起票したチケットID一覧 |
| `adrs` | string[] | 任意 | 議論中に決定したADRのID一覧 |

#### ADR

| 追加キー | 型 | 必須／任意 | 説明 |
| :--- | :--- | :--- | :--- |
| `superseded_by` | string \| null | 任意 | 後継ADRのID（`deprecated` で置換先がある場合に記載） |
| `tickets` | string[] | 任意 | 関連するチケットID一覧 |

#### Runbook実施記録

| 追加キー | 型 | 必須／任意 | 説明 |
| :--- | :--- | :--- | :--- |
| `runbook` | string | 必須 | 対象Runbookの `slug` |
| `followups` | string[] | 任意 | 引き継いだ議事録・チケットID一覧 |

## 3. 記録別の構成とテンプレート仕様

案件規模によるテンプレートの条件分岐は設けず、すべての種別で以下の一様な構成を使用する。
テンプレート実体は `management/templates/` 配下に配置する。

### 3.1. 議事録（`templates/discussion.md`）

単一Markdownファイルで管理し、以下の見出し構成とする。

1. `## 概要`：相談の主題と現在の結論を1〜2文で記載する。
2. `## 背景`：発端や気になっていること、実現したい変化を記載する。
3. `## 確認した事実と仮説`：確認できた事実と仮説を区別して記録する。
4. `## 議論・合意事項と理由`：合意内容、採用理由、検討した選択肢を記録する。
5. `## 未決事項`：次の判断に必要な未決事項、または保留・見送り理由を記録する。
6. `## 関連`：関連するADRや起票したチケットへの相対リンクを記載する。

### 3.2. ADR（`templates/adr.md`）

単一Markdownファイルで管理し、以下の見出し構成とする。

1. `## 概要`：決定の要旨を1〜2文で記載する。
2. `## 背景`：判断が必要となった文脈・課題・制約を記載する。
3. `## 決定事項`：採用した方針を明確に記述する。
4. `## 採用理由`：なぜその選択を採ったかの根拠を記載する。
5. `## 採用しなかった案`：比較した代替案と却下理由を記録する。
6. `## 影響と見直し条件`：導入・運用への影響と、再検討が必要になる条件を記録する。
7. `## 関連`：関連する議事録・チケット・後継ADRへの相対リンクを記載する。

### 3.3. チケット（1チケット1フォルダ構成）

長大ファイルの部分参照・部分更新を避けるため、チケットは以下の定型フォルダ構成とする。

```text
management/04.tickets/<YYYYMMDD-HHMMSS>-ticket-<slug>/
├── index.md                                    # 入口（テンプレート：ticket-index.md）
├── plan.md                                     # 合意仕様・ステップ・判断ログ（テンプレート：ticket-plan.md）
├── notes/                                      # 調査結果・詳細ログを 001-<slug>.md で追加（テンプレート：ticket-note.md）
├── artifacts/                                  # 任意：テストエビデンス・生ログ等の成果物置き場（運用は導入先委任）
└── review/
    ├── index.md                                # レビュー実施履歴＋自動生成指摘一覧（テンプレート：review-index.md）
    └── findings/
        └── <phase>-round<N>-<NNN>-<slug>.md    # 指摘1件1ファイル（テンプレート：review-finding.md）
```

各ファイルの必須見出し構成は以下のとおりとする。

* **`index.md`（入口）**
  1. `## 概要`：チケットの目的と要約。
  2. `## AC（受け入れ条件）`：本チケットで満たすべき検証可能な受け入れ条件。
  3. `## DoR（着手合意）`：任せる範囲、着手を妨げる未決事項、着手合意の記録。
  4. `## 現在地`：現在の状況、ブロッカー（確認待ち）、次に取る行動の数行サマリ（`phase`・`phase_status` は frontmatter、完了／未完了ステップの実体は `plan.md` で管理する）。
  5. `## 変更ファイル`：`<!-- AICO:AUTO:BEGIN:changed-files -->` 〜 `<!-- AICO:AUTO:END:changed-files -->` 内に、統合ブランチとの差分からプロジェクト資産の変更ファイル一覧をスクリプトで生成・更新する。
  6. `## DoD（完了の定義）`：ACごとの検証結果・根拠、未検証項目と人の判断結果、関連記録・ADRへの導線確認。
  7. `## 親子チケット・関連`：親・子チケット、議事録、ADRへの相対リンク。
* **`plan.md`（合意仕様と計画）**
  1. `## 合意した仕様`：必要な入出力、振る舞い、制約、対象外。
  2. `## ステップ一覧`：作業ステップをチェックリスト（`- [x]` / `- [ ]`）で管理し、完了済み・未完了の実体を一元管理する。
  3. `## 検証方針`：テスト・レビューの確認観点と対象環境。
  4. `## 判断ログ`：ADRにするほどではない個別判断の選択と理由。
* **`notes/<NNN>-<slug>.md`（個別記録）**
  * 長くなる調査結果、検証ログ、詳細検討を1件1ファイルで切り出す。
  * 見出しは `## 概要`・`## 内容`・`## 結論・残件` とする。
* **`artifacts/`（任意・成果物置き場）**
  * テストエビデンス、スクリーンショット、実行ログなどチケット対応に閉じた成果物を格納したい場合に作成する。内部の命名・運用規約は導入先プロジェクトに委ねる。
* **`review/index.md`（レビュー入口）**
  1. `## レビュー実施記録`：フェーズ・ラウンド・種別（初回レビュー／再レビュー）・日時・比較基点・実施者・実行環境・未確認事項を回次ごとに記録する。
  2. `## 指摘一覧`：`<!-- AICO:AUTO:BEGIN:findings -->` 〜 `<!-- AICO:AUTO:END:findings -->` 内にスクリプトで集計表を生成する。
* **`review/findings/<phase>-round<N>-<NNN>-<slug>.md`（指摘1件1ファイル）**
  1. `## 対象`：対象ファイル・行範囲・比較基点。
  2. `## 指摘内容と根拠`：問題点と仕様・実物に基づく根拠。
  3. `## 採否判断（人間選別）`：採用（`in-progress`）または見送り（`cancelled`）の判断と理由。
  4. `## 修正内容`：実施した修正の概要と関連コミット。
  5. `## 独立再確認結果`：独立コンテキストでの再確認結果、実行環境、未確認事項。

### 3.4. Runbook（手順書と実施記録）

繰り返し利用する手順書と、各回の実施記録を以下の構成で分離する。

```text
management/05.runbooks/<slug>/
├── runbook.md                                # 手順書（テンプレート：runbook.md）
└── records/
    └── <YYYYMMDD-HHMMSS>-<slug>/
        ├── index.md                          # 実施記録（テンプレート：runbook-record.md）
        └── review/                           # 任意：レビュー実施時に作成（構造はチケットの review/ と同一）
            ├── index.md                      # レビュー実施履歴＋自動生成指摘一覧（テンプレート：review-index.md）
            └── findings/
                └── round<N>-<NNN>-<slug>.md  # 指摘1件1ファイル（テンプレート：review-finding.md）
```

* **`runbook.md`（手順書）**：`## 概要`・`## 前提条件`・`## 入力`・`## 手順`・`## 完了条件`・`## 異常時の対応`・`## 改訂履歴`。
* **`records/<YYYYMMDD-HHMMSS>-<slug>/index.md`（実施記録）**：`## 概要`・`## ステップ実施状況`（完了済み・未完了・次に行うこと・判断理由）・`## 実行結果と添付`・`## 異常と引き継ぎ先`。
  実行ログや出力ファイル等の添付物は同じ記録フォルダ内へ格納し、相対リンクで参照する。
* **`records/<YYYYMMDD-HHMMSS>-<slug>/review/`（任意・レビュー記録）**：実施結果に対して独立レビューを行う場合に作成する。`index.md` および `findings/` の見出し・テンプレート構成はチケットの `review/` と同一とする（Runbook実施記録には `phase` および `phase_status` を設けないため、指摘ファイル名は `round<N>-<NNN>-<slug>.md` とする）。

## 4. 一覧生成仕様

各 `index.md` および管理ルートダッシュボードの一覧表は、対象ファイルのラベル付き自動生成ブロック（`<!-- AICO:AUTO:BEGIN:<id> -->` 〜 `<!-- AICO:AUTO:END:<id> -->`）内をスクリプトが元記録またはGit差分から再生成する。
空ディレクトリ（`notes/`・`review/findings/`・`records/`）には `.gitkeep` を配置せず、初回ファイル作成時にスクリプトがオンデマンドで生成する。
べき等性を保つため、自動生成ブロック内には実行時刻（生成日時）を出力しないこと。

| 対象ファイル | マーカー `<id>` | 生成する内容 | 列構成 | ソート順 |
| :--- | :--- | :--- | :--- | :--- |
| `management/index.md` | `summary`<br>`active-tickets` | 管理ルートダッシュボード。以下の2ブロックを生成する<br>・`summary`：区分サマリ（`02.discussions`〜`05.runbooks` の状態内訳件数と各 `index.md` へのリンク）<br>・`active-tickets`：進行中チケット（`active`）一覧（`closed` は掲載しない） | ・区分サマリ：区分 / 件数（状態内訳） / 一覧<br>・進行中チケット：ID（リンク） / タイトル / 状態 / フェーズ / 作業ブランチ / 更新日時 | ・区分サマリ：区分番号順<br>・進行中チケット：`created` 降順 |
| `management/02.discussions/index.md` | `list` | 議事録一覧（`archived/` 除く） | ID（リンク） / タイトル / 状態 / 更新日時 | `created` 降順 |
| `management/03.adr/index.md` | `list` | ADR一覧（`archived/` 除く） | ID（リンク） / タイトル / 状態 / 後継ADR / 更新日時 | `created` 降順 |
| `management/04.tickets/index.md` | `list` | チケット一覧（`archived/` 除く、`active` / `closed` 区分） | ID（リンク） / タイトル / 状態 / フェーズ / 作業ブランチ / 親チケット / 更新日時 | `created` 降順 |
| `management/05.runbooks/index.md` | `list` | Runbook一覧（`archived/` 除く） | Runbook（リンク） / タイトル / 最新実施日時 / 最新状態 | `slug` 昇順 |
| `<チケット>/index.md` | `changed-files` | チケットで変更したプロジェクト資産の一覧（統合ブランチとの差分） | 変更種別（`A` / `M` / `D` / `R`） / ファイルパス | ファイルパス昇順 |
| `<チケット>/review/index.md`<br>`<Runbook実施記録>/review/index.md` | `findings` | チケットまたはRunbook実施記録内のレビュー指摘一覧 | 指摘ID（リンク） / タイトル / 重要度 / 状態 / 更新日時 | フェーズ工程順（`drafting`→`planning`→`design`→`implementation`→`closing`、チケット時）・ラウンド数値昇順、同一ラウンド内は重要度（`critical`→`major`→`minor`）→ 番号昇順 |

`management/index.md` の区分サマリにおける件数（状態内訳、`archived/` 除く）は以下の書式で出力する。

* **議事録・チケット**：`active: N / closed: M`
* **ADR**：`accepted: N / open: M / その他: K`（`deprecated`・`cancelled` の合算）
* **Runbook**：`N件`（手順書数）

チケット一覧およびダッシュボードの「フェーズ」列は `<phase> / <phase_status>` の形式で表示する（例：`design / reviewing`、`closing / done`）。
`parent: null`・`superseded_by: null`・Runbook 未実施時など該当値がないセルは `-` と表示する。
管理ルートダッシュボード（`management/index.md`）には未統合の作業ブランチ上の途中進捗は含まれないため、冒頭（手書き領域または固定注記）に「統合済み記録の一覧であり、作業中の最新状況は各作業ブランチのチケット記録を確認すること」を明記する。
