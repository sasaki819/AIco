# 05. エージェント設定・同期・ワーカー仕様

## 概要

4つのAIツールで共通の協業手順とワーカー構成を維持するための設定仕様を定める。
本章では以下を定める。

* 対象ツールと配置マップ
* コンテキストファイルの構成
* スキル同期仕様
* 3段階ワーカー定義とモデル設定

## 1. 対象ツールと配置マップ

AIcoは以下の4ツールを対象とし、`aico-manifest.json` の `tools` 配列で有効化するツールを制御する。

| ツール | 識別子（`tools`） | コンテキストファイル | スキル参照先 | ワーカー定義パス |
| :--- | :--- | :--- | :--- | :--- |
| **Claude Code** | `claude` | `CLAUDE.md`（`@AGENTS.md` 参照） | `.claude/skills/`（同期先） | `.claude/agents/worker-{high,middle,low}.md` |
| **Codex** | `codex` | `AGENTS.md` | `.agents/skills/`（直接参照） | `.codex/agents/worker-{high,middle,low}.toml` |
| **Antigravity** | `antigravity` | `AGENTS.md` | `.agents/skills/`（直接参照） | `.agents/agents/worker-{high,middle,low}.md` |
| **GitHub Copilot（VS Code）** | `copilot` | `AGENTS.md` | `.github/skills/`（同期先） | `.github/agents/worker-{high,middle,low}.agent.md` |

共通運用におけるツール機能の採否と境界は以下のとおりとする。

* **Localハーネス除外**：VS Code環境では実行ハーネスを区別し、Localハーネス固有の探索先は共通運用の前提にしない。
* **不採用機能**：条件付き指示ルール（パス指定ルール等）および事前プロンプト形式は共通運用に採用せず、コンテキストファイルとスキルへ集約する。
* **セキュリティ設定の分離**：コマンド実行許可・承認要求・サンドボックス等の設定は導入先と利用者の環境方針へ委ね、AIco配布物には含めない。
* **ユーザーレベル設定との境界**：個人の好みや端末固有設定は `~/.agents/` 等のユーザーレベル設定で管理し、プロジェクト側のAIco設定へ持ち込まないこと。

## 2. コンテキストファイルの構成

### 2.1. `AGENTS.md`（共通規約マスター）

プロジェクトルートの `AGENTS.md` は、AIco由来領域（`<!-- AICO:BEGIN -->` 〜 `<!-- AICO:END -->`）と導入先プロジェクト固有領域（マーカー外）の共存ファイルとする。
マーカー内はコンテキスト肥大化を防ぐため簡潔に保ち、以下の4要素のみを記載する。

1. **AIcoの基本原則**：AI主導・人判断・スクリプト分離の原則、および管理ルート（`management/`）の位置づけ。
2. **作業開始時の確認手順**：`management/aico-manifest.json` と `management/index.md` を確認して現在状況を把握する手順。
3. **工程別スキル案内表**：どの場面でどの `aico-*` スキルを使用すべきかの対応表（詳細：`06`章）。
4. **詳細マニュアルへの参照リンク**：`management/01.manual/` 配下の Getting Started や詳細規約へのリンク。

長い個別手順や開発者向け解説は `management/01.manual/` または各スキル（`references/` 含む）へ逃がし、`AGENTS.md` マーカー内へ直書きしないこと。
導入先プロジェクト固有のビルド規約・ブランチ命名規約・worktree方針などはマーカー外へ記載する。

### 2.2. `CLAUDE.md` および重複管理の禁止

* **`CLAUDE.md`**：Claude Code 向けの入口として `@AGENTS.md` の1行のみを記載する（AIco由来領域）。配置・更新・削除は同期スクリプトへ一元化し、`tools` に `claude` が含まれる場合のみ生成・同期する（`claude` が除外された場合は `@AGENTS.md` のみで構成される AIco 管理の `CLAUDE.md` を削除する）。
* **重複禁止**：`GEMINI.md` や `.github/copilot-instructions.md` へ共通規約を重複記載してはならない。

## 3. スキル同期仕様

### 3.1. マスターと同期先

スキルの原本はすべて `.agents/skills/` に一元配置する。
同期対象は `aico-*` スキルに限定せず、**`.agents/skills/` 配下に配置された導入先固有スキルも含めた全スキル**とする。

同期スクリプトは `aico-manifest.json` の `tools` に従い、以下のルールでコピー同期を行う。

| 有効ツール | 同期動作 |
| :--- | :--- |
| `claude` | `.agents/skills/` 配下の全スキルディレクトリを `.claude/skills/` へミラー同期する |
| `copilot` | `.agents/skills/` 配下の全スキルディレクトリを `.github/skills/` へミラー同期する |
| `codex` / `antigravity` | `.agents/skills/` を直接参照するためコピー同期は不要 |

### 3.2. 同期の制約と検証

* **直接編集の禁止**：`.claude/skills/` および `.github/skills/` 配下を直接編集してはならない。変更は必ず `.agents/skills/` 側で行い、同期スクリプトを再実行する。
* **削除追従・ツール無効化・べき等性**：`.agents/skills/` から削除されたスキルは同期先からも削除する。`aico-manifest.json` の `tools` からツールが除外された場合も、無効化ツールの AIco 管理生成物（`CLAUDE.md`・`.claude/skills/`・`.github/skills/`・`worker-{high,middle,low}.*`）のみを削除し、導入先が独自追加したエージェント定義等は保持する。差分がない場合はファイルを書き換えないこと（`--dry-run` で事前確認可能とする）。
* **ドリフト検知**：`doctor` スクリプトは `.agents/skills/` と各同期先の内容一致を検査し、差分や未同期スキルがある場合はエラーとして報告する。

## 4. 3段階ワーカー定義とモデル設定

### 4.1. ワーカー役割の定義

スキルから呼び出すサブエージェントは、以下の3段階の役割名（フルスペル）に統一する。スキルごとに専用ワーカー定義を増やさないこと。

| 役割名 | 任せる作業 | 選定基準 |
| :--- | :--- | :--- |
| **`worker-high`** | 複雑な設計判断、難しい原因分析、深い調査 | 精度と推論力を優先する |
| **`worker-middle`** | 意図を汲む実装、一般的なレビュー、定型外の修正 | 精度・速度・コストのバランスを取る |
| **`worker-low`** | 決まった手順の実行、抽出・整形、定型的な報告 | 速度とコストを優先する |

### 4.2. モデル・推論強度のSSOT（`aico-manifest.json`）

具体的なモデルIDと推論強度（effort）は各ツールのワーカー定義ファイルへ直書きせず、`management/aico-manifest.json` の `worker_models` を唯一の原本（SSOT）とする。
すべてのツール×レベルについて、**`model` と `effort` の両キーを常に定義する**こと。

```json
"worker_models": {
  "claude": {
    "high": { "model": "", "effort": "" },
    "middle": { "model": "", "effort": "" },
    "low": { "model": "", "effort": "" }
  },
  "codex": {
    "high": { "model": "", "effort": "" },
    "middle": { "model": "", "effort": "" },
    "low": { "model": "", "effort": "" }
  },
  "antigravity": {
    "high": { "model": "", "effort": "" },
    "middle": { "model": "", "effort": "" },
    "low": { "model": "", "effort": "" }
  },
  "copilot": {
    "high": { "model": "", "effort": "" },
    "middle": { "model": "", "effort": "" },
    "low": { "model": "", "effort": "" }
  }
}
```

* **初期配布値**：AIco配布テンプレートでは全項目の初期値を空文字 `""` とし、特定モデル名を配布物へ固定しない。
* **導入先設定と適用**：導入先は利用ツールに対応する `model` および `effort` を `aico-manifest.json` へ記入し、同期スクリプトを実行して各ツールのワーカー定義ファイルへ一括反映する。
* **未設定検知**：`doctor` スクリプトは、`tools` に含まれるツールについて `model` が空文字の項目、および同期アダプターが `effort` 出力に対応しているツールで `effort` が空文字の項目を警告として報告する（`effort` 未対応ツールではキーの存在のみ検証し、空文字 `""` は警告対象外とする）。

### 4.3. ツール別ワーカー定義の出力仕様

同期スクリプトは、AIco由来の薄い共通アダプター本文（配置先：`management/templates/workers/worker-{high,middle,low}.md`）と `aico-manifest.json` の `worker_models` を組み合わせ、`tools` で有効化されたツールのワーカー定義ファイルを生成する。同期対象は `worker-{high,middle,low}.*` の固定ファイル名のみとし、導入先が各ツール `agents/` 配下へ独自追加したサブエージェント定義は削除・上書きしない。

| ツール | 生成先ファイル | 形式 | `model` / `effort` の出力マッピング |
| :--- | :--- | :--- | :--- |
| **Claude Code** | `.claude/agents/worker-{high,middle,low}.md` | Markdown＋YAML frontmatter | `name`, `description`, `model`, `effort` を frontmatter へ出力する |
| **Codex** | `.codex/agents/worker-{high,middle,low}.toml` | TOML | `name`, `description`, `model`, `model_reasoning_effort`, `developer_instructions` を出力する |
| **Antigravity** | `.agents/agents/worker-{high,middle,low}.md` | Markdown＋YAML frontmatter | `name`, `description`, `model`, `effort` を frontmatter へ出力する |
| **GitHub Copilot（VS Code）** | `.github/agents/worker-{high,middle,low}.agent.md` | Markdown＋YAML frontmatter | `name`, `description`, `model`, `effort` を frontmatter へ出力する |

出力時の制約は以下のとおりとする。

* **未設定値の安全な扱い**：`model` または `effort` が空文字 `""` の項目は、ツールが構文エラーを起こさないよう出力キーを省略するかコメントとして出力し、未設定のままでもファイル形式の妥当性を保つこと。
* **ツール固有キーの吸収**：ツールごとに `effort` に相当する設定キー名が異なる場合（例：Codex の `model_reasoning_effort`）や、ツール側が未対応の属性は、同期スクリプトのツール別アダプター内で吸収し、マニフェスト側のスキーマ（`model` / `effort`）を均一に保つ。
* **薄いアダプターの維持**：ワーカー定義の本文へ個別スキルの手順を複製してはならない。手順はスキル側で管理し、ワーカー定義には役割と一般的な実行原則のみを記載する。

### 4.4. 親エージェントからの委譲規約

親エージェントが `worker-high`・`worker-middle`・`worker-low` へ作業を委譲する際は、親セッションの会話履歴が引き継がれない前提で、以下の5点を必ずプロンプトへ明示すること。

1. **参照する手順書・スキルパス**：従うべきスキルや関連仕様書のパス。
2. **対象範囲**：読むべきファイル・調査対象・比較基点コミット等。
3. **入力条件・制約**：前提条件、対象外、守るべき規約。
4. **変更可否**：読み取り専用か、編集・ファイル作成を許可する範囲はどこか。
5. **期待する成果と報告形式**：出力先ファイルパスや返却すべき項目（確認した実行環境・未確認事項を含む）。
