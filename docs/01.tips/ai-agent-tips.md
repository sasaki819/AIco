# AIエージェントTips

## 概要

ここではAIとの協業をスムーズにすすめるためのポイントをガイドする。
コツ、AGENTS.mdのおすすめ設定、文書作成ガイドの３分野についてまとめている。

## コツ

### プロジェクトフォルダとは別に管理用フォルダを作る

- 調査用に作る一時的なスクリプトなどの置き場にする
- 指示内容をMarkdownで置いて読ませる（「C:\work\ticket-0023\文字コードの整合性調査.mdを読んで事前検討事項がないか確認して」、などと使う）
- 対応の記録の置き場にする（次項参照）

### Markdownに記録を残す

- AIとのセッションを見返さなくても済むように適宜会話内容をMarkdownにアウトプットする。
- メリットは主に３点ある。
  - **見返せる**：後で経緯／対応内容を確認しやすい（新しいセッションでAIに確認させてもちゃんと答えられる）
  - **作業を引き継げる**：エージェント／セッションに問題が起きても新しいセッションで作業を続行できる
  - **並行作業できる**：マルチセッションで分業できる
- 特に有効な物は下記。
  - **議事録**：セッション内に埋もれがちな筆頭。
    - 会話のはじめに「このMarkdownに適宜議論した内容を追記して」というだけでも効果あり。
  - **指摘内容**：指摘の内容と対応状況も記録するとスムーズ。
    - 一度対応不要と判断した指摘が、次のAIレビューで再度指摘に挙がるのを防ぐ。
    - ある指摘の対応で、過去の指摘対応がデグるのを防ぐ。
  - **TODOリスト**：ファイルに残せばコンテキスト圧縮で消えない、人が忘れても大丈夫。
  - **対応方針**：実際にファイル修正などを行う前に計画をファイルに出すと良い。
    - 多数のファイルを更新する場合などに作業ミス／作業漏れが起きにくい。
    - どこまで対応したかチェックを入れると作業を引き継ぎ易い。
  - **対応結果**：最終的な対応内容のレポートを出させて保存しておく。
    - 後から人に聞かれてもすぐに確認できる。
    - いずれプロジェクトを去る時の引き継ぎ資料に転用できるかも知れない。

### 対応中に発生した知見を資産化する

- 対応完了時に、「今回の対応で得た知見の中で、今後のために記憶しておくべき点を挙げて」と言う。
  挙がった内容を見て納得した物は「これとこれは今後のために覚えておいて。」と言う。
- AIの動作・出力が思った通りで無かった場合、指摘しつつ、「AGENTS.mdに追記して」と言う。
- 何度も同じような指示をしている場合、説明がややこしい場合、今後も同じ作業をしそうな場合、
  「今後、同様の作業が発生した時のために今の手順をSKILL化して」という。

## AGENTS.mdおすすめ設定

ユーザーレベルのコンテキストファイルに書くおすすめ内容を列挙する。

### 特におすすめTop5（ピックアップです。以下のセクションにも重複して現れます）

- ツールを実行する前に、目的を1行で示す（例：対象を確定するためにファイルを検索する）。
- ファイル変更や外部送信作業（pushなど）、時間がかかる調査は、事前に計画と方針を説明し、承認を得てから行う。
- 事前合意に含まれない作業が必要になった場合は改めてユーザーに説明し、承認を得る。
- 資料やファイル名などの誤記を見つけたら報告する。
- パスワードやトークンなどの秘密情報を、ファイルやログに書かない。見つけたら指摘する。

### コミュニケーション系

- 回答、コメント、ドキュメント、コミットメッセージは日本語で書く。
- 回答は短く簡潔に、結論から書く。
- 回答や質問では、どのファイルのどの部分の話かを具体的に示す。
- 判断に必要な情報が足りない場合は、ユーザーに質問する。
- 答えがわからない場合は「わからない」と答える。
- 資料やファイル名などの誤記を見つけたら報告する。
- 単純な確認は、対話用の質問ツール（利用可能な場合）で自由記入欄付きの選択肢として示す。
- 次の場合は質問ツールを使わず、ユーザーが番号で答えられるよう、番号付きの文章で質問する。
  - 複雑な質問
  - 単純な選択肢で答えられない質問
  - 質問の数が多い場合
  - 質問ツールが使えない場合
  - 回答文と同時に質問する必要がある場合

### 作業の進め方系

- ファイル変更や外部送信作業（pushなど）、時間がかかる調査は、事前に計画と方針を説明し、承認を得てから行う。
- ツールを実行する前に、目的を1行で示す（例：対象を確定するためにファイルを検索する）。
- 複数のコマンドを連続実行するときは、不要な一時ファイルを作らず `&&` 等で連結し、1回の実行にまとめてトークンを節約できないか検討する。
- 変更後は、既存のテストやリンターがあれば実行して結果を報告する。失敗したら、その出力をそのまま示す。
- 依頼の範囲外の変更はしない。必要だと思ったら提案にとどめる。
- スキルの実行時、終了時は下記を出力する
  - スキル`<スキル名>`を開始します
  - スキル`<スキル名>`を終了します。

### 環境系

作業環境で使えるツールを簡単に書いておくとAIがスムーズに作業できる。
環境によって様々なのでここでは例だけ記載する。

- 以下のツール／コマンドが使える
  - Python 3.13.7（コマンドは`py`）
  - node、npm、npx（イントラ上のレジストリを参照。公式へのプロキシあり）
  - JDK21（Azul Zulu）
  - Git Bash
  - Ripgrep

### 作文系

AIの作文能力は非常に重要。
単にAGENTS.mdに「結論ファーストで」、「回答は簡潔に」と書くだけでは足りない。
Markdown作成スキルを用意し、AGENTS.mdでは下記を書いておくことがおすすめ。

- Markdownファイルを出力・更新する際は必ず`write-markdown`スキルを使用すること

`write-markdown` スキルの内容は [write-markdown.md](write-markdown.md) を参照（好みと合わない部分は各自調整を）。
