# 01. コア・コンセプト

## 概要

AIcoのユーザーが全体思想を短時間で把握するための入口であり、後続する全章および仕様設計の判断基準とする。  
本章では以下を定める。

* **役割分担とフローの先導**：人・AI・スクリプトの責任分担
* **仕様を基準にした開発（SDD）**：合意した仕様に基づく実装と検証
* **再開可能な記録**：細分化した定型ファイルによる知識の外出し
* **規約と手順の分離**：コンテキストファイル・スキル・テンプレート等の役割分担
* **ブランチの分離**：共有情報と個別作業の更新範囲の分離
* **肥大化を防ぐ設計基準**：構造分岐の禁止と本質外要素の切り離し

## 1. 役割分担とフローの先導

AIcoでは、人・AI・スクリプトの3者がそれぞれの強みに集中する役割分担を採る。

| 主体 | 主な責任 | 担わないこと |
| :--- | :--- | :--- |
| **人** | 目的の提示、成果物の確認、判断・承認 | 細かな管理手順の記憶、定型記録の手作業維持 |
| **AI** | 調査、成果物の作成、検証、報告、次アクションの先導 | 人の承認を伴う仕様決定、推測による未決事項の補完 |
| **スクリプト** | 決まった規則に基づく検査、採番、一覧生成、移行処理 | 文脈に応じた意味の判断、自動コミット |

人は着手時に目的・完了条件・AIに任せる範囲を合意する。  
AIは合意した範囲で検証と報告までを進め、現在地に応じた次の行動や選択肢を提示してフローを先導すること。  
不明点や人の判断が必要な条件に当たった場合は、推測で補完してはならず、判明した事実と選択肢および推奨案を提示して判断を求めること。

## 2. 合意した仕様を基準にする（SDD）

会話だけで実装を進めず、合意した仕様を実装と検証の基準とする。  
検討した内容は合意事項と未決事項に分けてファイルへ残すこと。

* **実装前の明確化**：必要な入出力、振る舞い、制約、完了条件を実装前に合意する。
* **仕様に対する検証**：AIは現在の仕様を参照して実装し、完了時に仕様と実物の結果を照合して検証する。
* **変更時の同期**：仕様を変更する場合は、変更内容を先に合意したうえで仕様と実装を揃える。

## 3. 会話に依存せず再開できる記録を残す

セッションやAIツールが切り替わっても作業を継続できるよう、判断と再開に必要な情報をMarkdownファイルへ外出しする。  
会話ログを丸写しするのではなく、構造化された記録として維持すること。

* **再開に必要な要素**：合意事項、判断理由、完了済み事項、未完了事項、および次に行うことを記録する。
* **細分化された定型構造**：長大な単一ファイルの一部を位置特定して参照・更新する運用は避けること。  
  1チケット1フォルダ配下の定型ファイル群や、レビュー指摘の1件1ファイル管理など、役割・単位ごとに細分化した構成を採り、一覧はスクリプトで集計する。
* **共有の場**：プロジェクト管理情報はリポジトリ配下の専用管理ルートでGit管理し、人とAIが同じ原本を参照する。

## 4. 共通規約と作業手順の分離

AIのコンテキスト消費を抑えつつ再現性を高めるため、知識と仕組みを役割ごとに分離する。

| 要素 | 役割 |
| :--- | :--- |
| **コンテキストファイル** | 全作業に共通する規約、工程の全体構造、参照すべきスキルへの案内を記載する |
| **スキル** | 各作業工程の入力、手順、完了条件、報告形式を定義する |
| **テンプレート** | 各工程で作成する成果物・記録の書式を定める |
| **スクリプト** | 決まった規則で実行できる検査・生成・更新・移行を機械的に処理する |
| **サブエージェント** | 作業の難易度に応じたモデル役割を抽象化し、必要な資料と対象を渡して実行する |

定義されたすべての作業工程は、スキルベースで進められるように整備すること。

## 5. 共有情報と個別作業の分離

複数作業の並行進行で管理ファイルの競合や成果との不整合を起こさないよう、更新範囲とブランチを分離する。

* **統合ブランチの責務**：全体に関わる共有情報、起票、全体一覧の更新、およびクローズ処理を行う。
* **作業ブランチの責務**：個別チケットの成果物と作業記録を一体で更新し、完了時に成果と記録をまとめて統合する。
* **同時編集の回避**：作業ブランチから全体一覧などの共有ファイルを更新してはならない。

## 6. 肥大化を防ぐ設計基準

過去の運用で見られた過剰な儀式化や保守負荷の増大を防ぐため、以下の3つの基準を遵守すること。

* **規模による構造分岐の禁止**：案件の大小によって別のテンプレートや別の構造へ分岐させないこと。  
  ファイル構造とテンプレートは一様に整備し、案件規模に応じた調整は記述の詳細度のみで行う。
* **本質の外にある関心事の分離**：特定AIツール専用の独自構文、外部サービスのPR・MR自動送信、プロジェクト固有の並列実行方式（Git worktree運用など）はAIcoの中核に抱え込まないこと。
* **投資対効果による取捨選択**：仕組みやルールを追加する際は、確認待ち・手戻り・再開コスト・保守負荷を実際に減らせるかを基準に判断する。  
  手順を守ること自体が目的化するルールは導入しないこと。
