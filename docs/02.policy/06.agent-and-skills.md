# 06. エージェント・スキル方針

## 概要

複数のAIツールを切り替えても同じ協業手順を維持できるよう、ツール設定の全体像と設計基準を示す。
本章では以下を定める。

* **対象ツールと共通化の範囲**：4ツール対応と機能ごとの採用方針
* **コンテキストファイルの集約**：`AGENTS.md` をマスターとする構成
* **スキルの集約と記述方針**：全工程のスキル化と `.agents/skills/` 一元管理
* **ワーカーとモデル選択の分離**：3段階ワーカーによる抽象化
* **ユーザーレベル設定との境界**：個人設定とプロジェクト設定の分離

ツールごとの具体的な配置パスやモデル名の割り当ては仕様および導入先設定で定める。

## 1. 対象ツールと共通化の範囲

AIcoは、Claude Code、Codex、Antigravity、GitHub Copilot（VS Code）の4ツールを対象とする。
共通の作業手順は4ツールで利用できる書式に揃え、ツール固有の設定は必要最小限の範囲に限定して共通手順へ混ぜないこと。
VS Codeではモデル名だけでなく実行ハーネスを区別し、Localハーネス固有の探索先は共通運用の前提にしないこと。

ツールが提供する機能ごとの役割と採用方針は以下のとおりとする。

| 機能 | AIcoの方針 |
| :--- | :--- |
| **コンテキストファイル** | 共通規約、工程の構造、参照すべきスキルへの案内を記載する |
| **スキル** | 各作業工程の詳細な手順、完了条件、報告形式を定義する |
| **条件付きの指示ルール** | 共通運用には採用せず、コンテキストファイルとスキルで扱う |
| **サブエージェント** | `worker-high`・`worker-mid`・`worker-low` の3段階ワーカーを使う |
| **事前プロンプト** | 独立した形式を増やさず、再利用する手順はスキルへ集約する |

コマンドの実行許可・承認要求・サンドボックスなどのセキュリティ設定は、本集約方針の対象外とし、導入先と利用者の環境方針に従う。

## 2. コンテキストファイルの集約

プロジェクトルートの `AGENTS.md` を共通規約のマスターとし、全作業に共通する原則と工程別スキルへの案内のみを短く保つこと。
個別工程の長い手順はスキルや参照資料へ分離し、`AGENTS.md` の肥大化を防ぐ。

* **Claude Codeへの対応**：`AGENTS.md` を取り込む `@AGENTS.md` 参照のみを記載した `CLAUDE.md` を用意する。
* **重複管理の禁止**：`GEMINI.md` や `.github/copilot-instructions.md` へ同じ規約を重複記載しないこと。
* **読み込み確認**：導入時は、使用するツールで共通規約が実際に読み込まれることを確かめる。

## 3. スキルの集約と共通記述方針

定義されたすべての作業工程は、スキルベースで進められるように整備すること。
具体的なスキル一覧はポリシー段階で固定せず、仕様策定時に各工程からゼロベースで導出する。
あわせて、管理記録の品質を揃えるため、Markdown文書作成ルールを独立スキルとして導入する。

* **実体の一元化**：スキルの原本は `.agents/skills/` に集約し、Claude Code用（`.claude/skills/`）とCopilot用（`.github/skills/`）へスクリプトで同期する。
  同期先を直接編集してはならない。
* **命名規則**：スキル名は `aico-<対象>-<動作>` を基本とし、AIco全体を対象とする場合は `aico-<動作>` とする。
  フォルダ名とfrontmatterの `name` を一致させること。
* **共通書式**：frontmatterは `name` と `description` を基本とし、本文には入力・手順・完了条件・報告形式を記載する。
  長い補足手順はスキル内の `references/` へ分離する。
* **ツール依存構文の禁止**：特定ツール専用の引数置換やコマンド埋め込み構文に依存せず、共通の文章で記述すること。
* **共有スクリプトの利用**：機械処理はスキル内に複製せず、AIcoの共有スクリプトを呼び出す。

## 4. ワーカーの役割とモデル選択の分離

サブエージェント定義はツール別の薄いアダプターに徹し、共通の手順を複製しないこと。
スキルは役割名だけを指定し、具体的なモデル名はポリシーに固定せず導入環境で利用可能なモデルから割り当てる。

| 役割名 | 任せる作業 | モデルを選ぶ基準 |
| :--- | :--- | :--- |
| **`worker-high`** | 複雑な設計判断、難しい原因分析、深い調査 | 精度と推論力を優先する |
| **`worker-mid`** | 意図を汲む実装、一般的なレビュー、定型外の修正 | 精度・速度・コストのバランスを取る |
| **`worker-low`** | 決まった手順の実行、抽出・整形、定型的な報告 | 速度とコストを優先する |

スキルごとに専用のエージェント定義を増やさないこと。
親エージェントがサブエージェントへ作業を委譲する際は、親の会話履歴が渡ることを前提にせず、手順書パス・対象・入力条件・変更可否・期待する成果を明示すること。

## 5. ユーザーレベル設定との責務境界

個人の好みや端末固有の環境情報はユーザーレベル設定（`~/.agents/` 等）で管理し、AIcoのプロジェクト設定へ持ち込まないこと。
プロジェクトリポジトリ側には、チームとAIが共有すべき協業フロー・規約・スキルのみを配置し、個人設定と責務を分離する。
